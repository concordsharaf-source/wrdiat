# نظام الورديات (wrdiat)

تطبيق عام لأي مؤسسة أو فرع: قناة، مطعم، مستشفى…

## الدخول — بدون أرقام دخول
- **الجميع يدخل التطبيق مباشرة في وضع الاطلاع:** تظهر الورديات والتقويم والإحصائيات فوراً لأي شخص يفتح الصفحة — لا حاجة لأسماء أو أرقام.
- **دخول الأدمن فقط:** زر **🔑/⚙️** في الأعلى يفتح نافذة دخول بالإيميل وكلمة المرور (أول إيميل يُسجَّل يصبح أدمن). الأدمن وحده يعدّل: الأقسام، الموظفين، قواعد الورديات، التبديل عند الغياب.
- **الجلسة دائمة للأدمن:** لا يخرج إلا بضغط «تسجيل الخروج» — ولا يُطلب إدخال كلمة المرور عند كل فتح.
- الموظفون لا يسجّلون دخولاً: يُعرضون بالاسم فقط (الاسم كاملاً أو الاسم واللقب).

## الأقسام
عدد غير محدود (صوت، تصوير، مطبخ، كاشير…)، ويمكن **تعديل اسم القسم** بزر «✏️ تعديل الاسم» بجوار زر الحذف.

## شاشة الإعدادات — 3 أزرار
داخل الإعدادات (للأدمن) ثلاثة أزرار تبويب: **🏢 الأقسام** · **👥 الموظفون** · **🗓️ الورديات** — كل واحدة تعرض محتواها وحده.

## اليوم
يمكن تقسيم اليوم لأكثر من موظف بفترات: من – إلى.

## توزيع الورديات الأسبوعي (تلقائي / تناوب) — بالنطاقات
في **الإعدادات ← توزيع الورديات الأسبوعي** زرّان كبيران في الأعلى:
- **📅 بالأيام:** بطاقة لكل يوم من أيام الأسبوع، وداخلها قاعدة عامة + قاعدة كل قسم — كلها **مطوية** ولا تظهر إلا بالضغط، ويظهر فيه تلميح يوجّه لزر الحفظ (لا أزرار حفظ فيه).
- **🏢 بالأقسام:** بطاقة لكل قسم مطوية بأيامه السبعة + زر حفظ واحد تحته.

البيانات في الحالتين مطوية — لا يظهر شيء قبل الضغط على البطاقة المطلوبة.
- **🌐 قاعدة عامة (كل الأقسام)** + **🏢 قاعدة مستقلة لكل قسم** — كل قسم بخصائصه: مثلاً السبت *ثابت* في قسم الصوت و*تناوب* في قسم التصوير، وهكذا لبقية الأيام.
- **الدمج:** اليوم الواحد يجمع كل النطاقات — سطر عام + سطر لكل قسم يخصّ حالة ذلك اليوم (ثابت من قسم + تناوب من قسم آخر في نفس اليوم = ورديتان).
- **تلقائي — نفس الموظفين كل أسبوع** (الخيار الأول): يمكن اختيار **أكثر من موظف** في السطر الواحد، فيظهرون جميعاً في بطاقة اليوم كل أسبوع (مثال: أحمد + خالد في كل سبت).
- **تناوب — دور أسبوعي** (الخيار الثاني): قائمة موظفين بترتيب محدد (أزرار ▲▼ لتغيير الترتيب)، يدور الدور أسبوعاً بعد أسبوع من **تاريخ بداية التناوب**، ويُضاف صاحب الدور فوق التلقائيين.
- **الدمج:** اليوم يعرض الكل معاً — كل الثابتين من كل الأقسام + صاحب الدور لكل أسبوع (مثال: [أحمد، خالد، سعيد] ثم الأسبوع التالي [أحمد، خالد، فاطمة]).
- **توليد هذا الأسبوع** دمج تراكمي: يبني التلقائيات فوق اليدوية والموجودة (لا يتجاهل الأيام).
- اسم القسم يظهر بجانب كل موظف في شرائح القاعدة العامة.
- **الوقت:** فترة الوردية (من / إلى) اختيارية لكل سطر.

### أزرار التنفيذ
- **💾 زر حفظ واحد تحت كل قسم** (في وضع «🏢 بالأقسام»): يقرأ كل الأيام المدخلة لذلك القسم — أياً كان وضع العرض الذي عُدّل فيه — ويطبّقها فوراً على الأسابيع القادمة حتى **5 سنوات** — **بدون تحديد تواريخ**: التلقائي يظهر في كل أسبوع، والتناوب يتحرك أسبوعاً بأسبوع (السبت الأول ← أول الدور، الثاني ← التالي… وهكذا).
- **التعديلات لا تضيع بين العرضين:** تعديل أي صف (النوع/الوقت/الموظفون) يُسجَّل فوراً، فيبقى محفوظاً عند التبديل من «بالأيام» إلى «بالأقسام» قبل الحفظ.
- **لا توجد أزرار سفلية منفصلة** ولا أزرار حفظ تحت الأيام — التطبيق لكل 5 سنوات مدمج في زر الحفظ الوحيد تحت كل قسم.

الورديات المولَّدة تلقائياً تحمل شارة **⚡ تلقائي** في صفحة اليوم والتقويم، ويمكن حذفها أو تعديلها يدوياً كأي وردية.

## تبديل سريع من بطاقة اليوم (غياب / تغطية)
- اضغط على **اسم الموظف** في بطاقة اليوم (صفحة 📅) ← تظهر نافذة بموظفي **قسمه فقط** — طباخ يُبدَّل بطُبّاخ، وكاشير بكاشير… ولا يظهر أحد من الأقسام الأخرى. (الموظف بدون قسم تظهر كل مجموعته.)
- اختر البديل ← تُستبدل الوردية فوراً (يبقى وقتها كما هو)، وتُسجَّل العملية في `swapLog` في قاعدة البيانات (من/إلى/من نفّذ/متى).
- التبديل اليدوي يلغي صفة «تلقائي ⚡» عن تلك الوردية فقط، ولا يمس القواعد.
- الموظف الموقوف لا يظهر كخيار، وإن لم يوجد بديل تظهر رسالة واضحة.

## إدارة الموظفين بعد الحفظ
- كل موظف في القائمة له زر **تعديل** (يعبّئ النموذج ويحفظ التعديلات — حتى تغيير رقم الدخول)، وزر **إيقاف / تفعيل** (الموقوف لا يدخل التوزيع ولا يسجّل الدخول، ويبقى ظاهراً لإعادة تفعيله)، وزر **حذف**.
- زر **إلغاء التعديل** يعيد النموذج لحالة الإضافة الجديدة.

## ملاحظات
- الموظف **المعطَّل** لا يدخل الدورات إطلاقاً.
- القواعد والورديات والأقسام والموظفون يُخزَّنون محلياً (localStorage) أيضاً — يعمل التطبيق أثناء انقطاع الشبكة ويُزامن عند عودتها.
- بنية القواعد في Firebase: `scheduleRules = { anchor: '2026-8-1', scopes: { '': { days: {0..6:{rows:[...]}} }, deptId: { days: {...} } } }` — والقواعد القديمة بصيغة `days` تُرحَّل تلقائياً.

بيانات Firebase تحت `sessions/_wrdiat_org/` حتى لا تختلط مع تطبيقات أخرى.
