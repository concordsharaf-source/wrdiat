# نظام الورديات (wrdiat)

تطبيق عام لأي مؤسسة أو فرع: قناة، مطعم، مستشفى…

## الدخول
- **الأدمن:** أول إيميل يُسجَّل يصبح الأدمن.
- **الموظف:** **اسمه** + **رقم دخول** يمنحه الأدمن.
- عرض الاسم: كاملاً، أو الاسم واللقب.
- **الجلسة دائمة:** لا يخرج المستخدم إلا بضغط «تسجيل الخروج» — الجلسة محفوظة على الجهاز وتُستعاد فوراً حتى بدون إنترنت (مع عرض آخر البيانات المخزنة)، ولا يُطلب إدخال كلمة المرور مجدداً. الخروج التلقائي يحدث فقط إذا أوقف الأدمن الحساب أو حذفه، أو عند الضغط على زر الخروج.

## الأقسام
عدد غير محدود (صوت، تصوير، مطبخ، كاشير…).

## اليوم
يمكن تقسيم اليوم لأكثر من موظف بفترات: من – إلى.

## توزيع الورديات الأسبوعي (ثابت / تناوب) — جديد
في **الإعدادات ← توزيع الورديات الأسبوعي** يضع الأدمن قاعدة لكل يوم من أيام الأسبوع، وقد يحتوي اليوم على أكثر من سطر (وردية لكل سطر):

- **موظف ثابت:** نفس الموظف كل أسبوع في ذلك اليوم.
- **بالتناوب:** قائمة موظفين بترتيب محدد، يدور الدور بينهم أسبوعاً بعد أسبوع — وترتيب الدور قابل للتعديل بأزرار ▲▼.
- **القسم:** يمكن حصر التوزيع بقسم معين (بدون قسم = كل الموظفين النشطين).
- **الوقت:** فترة الوردية (من / إلى) اختيارية.
- **تاريخ بداية التناوب:** تُحسب منه دورية الترتيب، وتغييره يعيد ضبط التسلسل من جديد.

### أزرار التنفيذ
- **توليد هذا الأسبوع:** يملأ أيام الأسبوع الحالي الفارغة فقط (لا يمس الأيام التي فيها ورديات).
- **تطبيق التوزيع على سنة قادمة:** يبني الورديات من اليوم وحتى سنة كاملة؛ الورديات اليدوية في الماضي تبقى، واليدوية المستقبلية تُستبدل بالبنية التلقائية.

الورديات المولَّدة تلقائياً تحمل شارة **⚡ تلقائي** في صفحة اليوم والتقويم، ويمكن حذفها أو تعديلها يدوياً كأي وردية.

### ملاحظات
- الموظف **المعطَّل** (disabled) لا يدخل الدورات إطلاقاً.
- القواعد والورديات تُخزَّن محلياً (localStorage) أيضاً، فيعمل التطبيق أثناء انقطاع الشبكة ويُزامن عند عودتها.
- بنية القواعد في Firebase: `scheduleRules = { anchor: '2026-8-1', days: { 0..6: { rows: [...] } } }`.

بيانات Firebase تحت `sessions/_wrdiat_org/` حتى لا تختلط مع تطبيقات أخرى.
